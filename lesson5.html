Lesson 5 · 自由專題

學識嘅係方法，唔係一個 app　·　嶺南衡怡紀念中學　·　按「複製」→ 貼落 Cursor
點用呢張卡？
  1. 開 Cursor，打開你下載返嚟嘅 template 資料夾
  2. 右邊 Chat 面板，左下角揀 Agent 模式
  3. 撳下面任何一句嘅 「複製」
  4. 貼落 Cursor 對話框 → 按 Enter
  5. AI 寫完之後，一定要撳右上角 「Keep All」，再回瀏覽器 重新整理

今日冇指定題目。巴士可以、天氣可以、Pokémon 可以、書同股票都可以。 因為你學嘅係方法：搞清楚要咩資料 → 搵到提供資料嘅 API → 填 5 個 function → 發布。
PART 0

熱身：個骨架係點運作嘅？

同一副骨架，換一個資料來源就變成另一個 app。先叫 AI 拆開嚟講清楚。

0睇清楚個骨架

唔改任何嘢，先搞清楚 5 個 function 各自負責咩
請睇下 @app.js（我啱啱下載返嚟嘅 template）。唔准改任何嘢，我淨係想知：

1. 呢個骨架係靠邊 5 個 function 撐起？
   （loadList / showDetail / showInfo / loadOther / startAutoRefresh）
2. 逐個講：輸入係咩、做咩、最後會喺畫面邊個位置顯示嘢。
3. 邊幾個位置有 // TODO 未填？
4. 如果我今日只係換一個完全唔同嘅資料來源（換一個 API），
   理論上需要改邊幾個 function？要唔要改 HTML？

用最簡單嘅講法，我係中三學生。
你要檢查咩：AI 答嘅，同你自己打開 app.js 睇到嘅係唔係一樣？
點驗：攞住佢講嘅 function 名，喺 Cursor 用搜尋（Cmd + F）搵一次，真嘅存在嗎？
重點答案：通常只需要換 loadList() 裡面嘅 API 網址同解析方式， HTML 幾乎唔使改 —— 呢句就係今日嘅全部秘密。
PART 1

五步，由一個 template 去到你自己嘅 app

跟住做。每個 step 做完撳 Keep All ＋ 重新整理。換一句 API，就換到題目 —— 呢頁學嘅係「方法」。

1下載 Template

目標：解壓、Cursor 開到、喺 localhost 真嘅跑起
請一步一步教我由零開始，用一個 template 開一個新專案。我係中學生，未用過 Terminal。

1. 先教我下載呢個 ZIP（我只想下載 ZIP，唔要 clone、唔要用 git）：
   https://github.com/kelvin0611/c0713a-template/archive/refs/heads/main.zip
   （下載完叫咩檔名？會喺邊個資料夾？）
2. 教我解壓縮（macOS 上面點做），解壓完個資料夾叫咩名。
3. 教我喺 Cursor 用「Open Folder」打開嗰個資料夾
   （⚠️ 記住要開裡面有 index.html 嘅那一層，唔好開到外層）。
4. 教我喺 Cursor 嘅 Terminal 跑起個 server，同埋喺瀏覽器打開邊個網址。
5. 話我知跑得成功嘅話，畫面應該見到咩。
6. ⚠️ 如果我直接雙擊 index.html 打開，會發生咩事？為咩會咁？
7. 教我點樣停咗個 server。
你要檢查咩： ✅ 佢教你用 python3 -m http.server 8000，然後開 http://localhost:8000。
✅ 佢有講「唔可以雙擊 index.html」—— 因為咁樣係 file://， 會令 fetch 同 localStorage 出事，畫面一片空白。
✅ 你自己真嘅見到個 template 畫面（唔係一片白、唔係一堆文字）。
⚠️ 見到「connection refused」→ server 未跑起，返 Terminal 睇下係唔係出咗錯。
⚠️ 唔好將個 ZIP 解壓去 Desktop 再開，好容易開錯層。放喺 Projects 之類嘅位置，一層一層睇清楚。

2定題目：你想要咩資料？

目標：唔係「我想整一個 app」，而係「我想要咩資料」
我想用呢個 template 做我自己嘅 app，但未想到做咩。請幫我諗。

第一步（好重要）：先問我 3 條問題，了解我想要咩資料。
例如：你平時最想知咩？鍾意咩事物？你想要「一覽表」定係「詳細資料」？

第二步：等我答完之後，推薦 3 個題目。每個題目都要寫：
- 個 app 幫人做咩（一句話）
- 用邊個資料來源（大概係邊個 API、提供咩資料）
- 難度：可唔可以 1 個鐘內做到？
- 畫面大概長咩樣（列表？詳情？）

第三步：列完之後停手，等我揀。

⚠️ 唔准喺我未揀之前寫任何 code，亦唔准自己幫我決定題目。
⚠️ 唔准推薦要輸入個人資料（身分證、地址、銀行、醫療）嘅題目。
你要檢查咩： ✅ 佢有先問你才推薦 —— 呢個就係跟指示。
❌ 如果佢一口氣推薦咗又自己開始寫 code（或者自己幫你揀咗）→ 冇跟指示，可以直接叫停佢。
❌ 推薦要你登入、要 API key、或者要你畀個人資料嘅題目 → 唔要。
你自己揀題目嘅方法：揀一個你真係想知嘅資料。想知，你才會做得完。

3摻 API（要真 curl 驗一次）

目標：搵到一個免 API key、有 CORS、真嘅攞得到資料嘅 API
我揀咗題目：（填你揀嘅題目，例如：睇 Pokemon 資料 / 睇匯率 / 睇天氣 / 睇書）。

請推薦可以用嘅公開 API。硬性條件（唔符合就唔准推薦）：
1. 唔需要 API key、唔需要註冊、唔需要登入
2. 支援 CORS（即係可以由本地網頁同 GitHub Pages 直接 fetch）
3. 回傳 JSON，格式清楚

請畀我 2–3 個選擇，每個都寫：
- 完整網址（連參數）
- 回傳格式：舉一個真嘅 JSON 例子（唔准自己作數據）
- 有咩限制（速率限制、覆蓋範圍、語言、會唔會忽然死）
- 一個要小心嘅位

⚠️ 最緊要嘅一步：你一定要真嘅驗證。請畀我一條 curl 命令，
叫我自己喺 Terminal 行一次，例如：
    curl -s "（網址）" | head -c 500
並且話我知：行完應該見到咩、見到咩就代表唔 work。

如果你唔肯定個 API 而家仲有冇效，就直接講「唔肯定」，
唔准假設一定得。唔准自己作一個網址出嚟。
你要檢查咩： ✅ 最實際嘅檢查：copy 條 curl 落 Terminal 真嘅行一次 —— 有真嘅 JSON 返嚟嗎？ （要睇到真數據，唔係 {"error":"..."} 或者 404。）
✅ 喺瀏覽器直接開嗰條網址，見得到 JSON → 通常代表 CORS 有機會 OK。
❌ AI 話「呢個 API 應該可以用」但係冇 curl 過 → 懷疑佢，自己試。
❌ 佢畀你一個要 ?api_key=xxxxx 嘅網址 → 換過另一個。
❌ 佢自己作咗一段 JSON 出嚟當例子（數字靚到假）→ 唔好信。
⚠️ API 係會死、會改格式嘅。所以今日學嘅係「點驗一個 API」，唔係「呢個 API 一定得」。

4填 5 個 function

目標：骨架有血有肉，列表、詳情、錯誤訊息都出得到
請打開 @app.js，填好呢 5 個 function。用我上面 curl 驗證過嘅 API：
（貼上你驗證過嘅 API 網址同回傳格式）

1. loadList()
   —— fetch 個 API，攞資料，做成一個列表放入 id="list"
   —— 每一項要能分辨身份（例如有 id / code），畀之後撳入去查詳情用
2. showDetail(id)
   —— 用戶撳某一項之後，攞同顯示該項嘅詳情放入 id="detail"
   —— 如果詳情已經喺列表資料裡面，就唔好再 fetch 一次（重用已有資料）
3. showInfo(msg)
   —— 顯示狀態／錯誤訊息（「載入中…」「網絡有問題，等陣再試」「搵唔到資料」）
   —— 一律用人話，唔可以顯示英文 error 或者出紅字
4. loadOther()
   —— 攞第二種相關資料（例如另一個分類、或者補充資料），放入 id="other"
5. startAutoRefresh(seconds)
   —— 每 N 秒自動更新。⚠️ 一定要先 clearInterval 清走舊 timer 才開新嘅
   —— 唔清就會愈跑愈快；亦唔可以重複開多過一個 timer

硬性要求：
- 每個 function 都要有 try / catch，出錯要用 showInfo() 講人話
- 每次 fetch 之後要檢查 response.ok
- 5 個 function 開頭各寫一句中文註釋，講明佢做咩
- 唔准改 HTML 嘅 id 名、唔准改 CSS
- 資料嚟自 API 嘅話，唔准寫死假數據當係真

寫完之後：
(a) 話畀我知邊個 function 對應畫面邊部分
(b) 列出「你覺得呢次最可能出錯嘅 3 個位」，等我逐個檢查
你要檢查咩： ✅ 5 個 function 真嘅都填咗？喺 Cursor 搵 TODO 應該搵唔到（或者只有一個）。
✅ 畫面：列表出到嘢、撳入去出詳情、出錯有人話（斷網試一次，睇下會唔會出「網絡有問題」）。
✅ Console 冇紅字（F12 → Console）。
❌ 最易捉到嘅錯：setInterval 出現咗兩次（timer 會愈跑愈快）； 或者 showDetail() 又 fetch 一次已經有嘅資料。
✅ 佢有冇列出自己「最可能出錯嘅 3 個位」—— 呢啲位你就去驗。
⚠️ 換一句 API 就換到題目。呢 5 個 function 填完，你以後任何題目都係填呢 5 個 —— 呢個就係今日學嘅「方法」。

5發布（同 Lesson 4 一樣）

目標：你第二個 app 都有一個真嘅網址
跟返 Lesson 4 嘅流程，幫我將呢個新 app 發布上 GitHub Pages。請逐步嚟：

1. 「發布前檢查」：清走 console.log、有冇破圖、手機（400px）會唔會爆版、
   有冇寫死嘅測試假數據、標題有冇寫好
2. 寫一個 README.md：呢個 app 做咩、點跑、資料來源（邊個 API、要唔要 API key）、
   技術（純 HTML/CSS/JS）。⚠️ 唔准加入我嘅全名或個人資料。
3. 逐句教我：git init → git add → git commit → git branch -M main →
   git remote add origin（我嘅新 repo 網址）→ git push -u origin main
   —— 每一句都講：做咩、成功會見到咩、失敗最常見係咩原因
4. 教我喺 GitHub 網頁開 GitHub Pages（Settings → Pages → Deploy from a branch →
   main → / (root) → Save），然後等 1–3 分鐘
5. 最後畀我一段可以分享嘅文案（一句話 ＋ 我條網址）

⚠️ 安全規矩：
- 唔准叫我將密碼、token、API key 或個人資料寫入任何檔案、命令或 commit 訊息
- 登入我自己做，唔准叫我貼任何密碼或 token 落任何地方
- 呢個係一個全新嘅 repo，唔准搞亂我之前 Lesson 4 嘅專案
你要檢查咩： ✅ 你條網址用手機開得到，而且 app 裡面真係出到資料（唔係空白、唔係永遠「載入中…」）。
✅ 換一句 API 就換到題目 —— 如果你仲有時間，再叫 AI 換第二個 API 落 loadList()， 睇下係唔係改一個 function 就做到全新 app。做得到，你就真嘅學識咗「方法」。
❌ 佢叫你貼 token／密碼 → 唔好照做，當場停。
✅ 確認你 Lesson 4 嗰個舊 repo 冇被改（去 GitHub 睇下最後 commit 時間）。
⚠️ 交功課前：呢個網址就係你今日嘅成果。答得出「我個 app 用咩資料、邊度嚟、點更新」，就算完成。

?壞咗點算？

API 死咗、CORS 爆、頁面空白 —— 把原句錯誤「交畀」AI
我做自由專題途中出現咗問題，請幫我一步步解決：

我做到邊一步：
[例如：填完 loadList() 之後 / 網址改做自己嗰個 API 之後]
我打咗咩 / 改咗咩：
[貼上你改嘅 code 或者命令]
見到咩錯誤（原句 copy 過嚟，唔要改字）：
[按 F12 → Console 貼紅字，或者 Terminal 貼紅字]
我期望應該發生：
[例如：見到一個列表]

請：
1. 先解釋呢個錯誤係咩意思（用中學生聽得明嘅講法）
2. 判斷係邊一種：API 冇回應？CORS 被阻？JSON 格式同你想像唔同？定係 code 寫錯？
3. 一步一步教我修，改最少嘅嘢，唔好改其他正常嘅部分

⚠️ 唔准自己作一個「假數據」去遮住個錯誤。我要知真正原因。
常見三種：CORS policy → 呢個 API 唔可以由網頁直接 fetch，換過一個； Failed to fetch → 網址打錯或者 API 死咗，自己 curl 再驗一次； Cannot read properties of undefined → JSON 格式同 code 假設唔同，叫 AI 印返個實際回傳睇。
AI 改爛咗？同佢講：「請還原上一步嘅改動」。
卡死超過 15 分鐘：叫 AI「用最簡單嘅方法，先出一個純文字列表，唔要靚」—— 行得通再慢慢加。
